## 本课目标

前置：已跑通第 15 课项目。能解释一条任务在 Java 对象和数据库行之间怎样转换，并验证服务重启后数据仍存在。

## 第一步：从表结构开始

打开 `src/main/resources/schema.sql`：

```sql
CREATE TABLE IF NOT EXISTS tasks (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title VARCHAR(80) NOT NULL,
  done BOOLEAN NOT NULL DEFAULT FALSE
);
```

行代表一条任务，列代表属性；主键唯一标识行，identity 让数据库生成 id。NOT NULL 限制空值，不等于拒绝空白文本；长度约束与标题非空校验分别解决不同问题。

IF NOT EXISTS 使重复启动不会因为表已存在而失败，**不会自动把旧表迁移成新结构**。后续改字段应学习数据库迁移，不要依赖删除数据重建来模拟正式升级。

## 第二步：逐项对应 CRUD

| 操作 | SQL 形状 | 项目方法 |
| --- | --- | --- |
| 列表 | SELECT ... ORDER BY id | findAll |
| 单条 | SELECT ... WHERE id = ? | find |
| 新增 | INSERT INTO tasks ... | create |
| 更新 | UPDATE tasks SET done = ? WHERE id = ? | updateDone |
| 删除 | DELETE FROM tasks WHERE id = ? | delete |

不写 ORDER BY 时不能保证顺序。更新或删除返回影响行数，0 表示没匹配到记录，Service 据此返回 404。不同数据库方言和驱动行为仍需核对，不能只在 H2 通过就断言所有数据库完全一致。

## 第三步：参数绑定怎样保护查询结构

TaskRepository 中的片段：

```java
return jdbc.update("UPDATE tasks SET done = ? WHERE id = ?", done, id);
```

SQL 模板和参数分开传入，用户内容作为数据处理。不要拼接 `"WHERE title = '" + title + "'"`。参数占位符不能替代表名、列名和排序方向；动态选择列时需要从受控白名单生成结构。

RowMapper 把结果集的一行转换为 Task。生成主键使用 GeneratedKeyHolder，数据库负责分配，不要用 `SELECT MAX(id) + 1`，并发创建时会冲突。

## 第四步：实际验证持久化

1. 创建一个明显不同的标题，如 `Persistence checkpoint`，记录返回 id。
2. 在运行服务的终端按 Ctrl+C，等待退出。
3. 从**同一个项目目录**再次启动，再查询该 id。
4. 检查运行目录的 data 文件夹；不要同时启动两个进程占用同一个 H2 文件。

连接 `jdbc:h2:file:./data/tasks` 使用磁盘文件，测试的 `jdbc:h2:mem:tests` 使用内存。换工作目录会解析到另一份相对路径，不能据此断言原数据丢失。

## 第五步：事务保证一组操作的提交边界

Service 上的 `@Transactional` 让一次通过 Spring 代理调用的业务方法参与事务。默认遇到未捕获运行时异常会回滚；受检异常默认规则不同，需要按需求配置。

如果“更新完成状态”和“写操作日志”必须同时成功，应放在同一事务里。把异常 catch 后正常返回，事务可能照常提交。同对象内部直接调用另一个带注解的方法，通常不会经过代理，不能因此得到预期的新事务行为。

事务不等于所有并发问题消失。两个客户端同时改一个任务，当前教学项目可能出现后写覆盖前写；版本号乐观锁、条件更新和隔离级别需要进一步设计。

## 动手任务

1. 为列表添加 `done=true` 过滤时，写出带参数的 SQL，不拼接参数文本。
2. 如果把 VARCHAR(80) 改为 VARCHAR(40)，现有数据库会因为重启就变化吗？已有长标题应如何处理？

<details>
<summary>参考解法与检查点</summary>

第一题 `SELECT id, title, done FROM tasks WHERE done = ? ORDER BY id`，把 Boolean 值作为参数。第二题不会，表已存在时 CREATE 被跳过。需要显式迁移，并提前决定旧数据的合法处理方式；不能在不告知用户的情况下截断标题。请求校验、Service 与数据库约束应保持一致。
