## 本课目标

前置：对象与循环。能按照“有顺序、去重、按键查询”的需求选择集合，读懂泛型参数，避免集合元素类型混乱。

## 第一步：按问题选容器

| 需求 | 接口 | 本课选择的实现 |
| --- | --- | --- |
| 保留有序任务，可重复 | List | ArrayList |
| 标签去重 | Set | LinkedHashSet 保留插入顺序 |
| 由 id 找任务 | Map | LinkedHashMap 便于稳定展示 |

HashSet、HashMap 不保证迭代顺序。示例需要稳定输出时，应选择有顺序约定的实现，不能把本机恰好看到的顺序当标准。

## 第二步：用一个程序完成三种操作

```java title="Main.java"
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

public class Main {
    record Task(long id, String title) {}

    public static void main(String[] args) {
        List<Task> tasks = new ArrayList<>();
        tasks.add(new Task(1, "Java"));
        tasks.add(new Task(2, "SQL"));
        Set<String> tags = new LinkedHashSet<>(List.of("Java", "SQL", "Java"));
        Map<Long, Task> byId = new LinkedHashMap<>();
        for (Task task : tasks) byId.put(task.id(), task);
        Map<String, Integer> counts = new LinkedHashMap<>();
        for (String word : List.of("java", "sql", "java")) {
            counts.merge(word, 1, Integer::sum);
        }
        System.out.println(tasks.size());
        System.out.println(tags);
        System.out.println(byId.get(2L).title());
        System.out.println(counts);
    }
}
```

```text title="运行输出"
2
[Java, SQL]
SQL
{java=2, sql=1}
```

`List<Task>` 让编译器只允许添加 Task，而不是混入 String。`<>` 根据左边推断类型参数。Map 的两个参数分别是键类型和值类型，Long 是 long 的包装类；`get(2L)` 与 `get(2)` 的包装类型不同，不能指望它们匹配同一个键。

merge 中的 `Integer::sum` 是“已有值与新值相加”的方法引用；不用这个语法也可写 `counts.put(word, counts.getOrDefault(word, 0) + 1)`。

## 第三步：去重依据是什么

Set 不是读取字段后自动判断“看起来一样”。哈希集合依赖 equals 和 hashCode：相等对象必须有相同哈希值，但相同哈希值不一定相等。

record 自动提供基于组件的 equals/hashCode。普通类如需按业务值相等，应成对设计这两个方法。不要在对象作为哈希键后修改参与相等性计算的字段，否则可能再也找不到它。

## 第四步：泛型与可变性

`List<String>` 不能直接赋给 `List<Object>`；否则后者可以放进 Integer，破坏前者“都是字符串”的约定。`List<? extends Number>` 表示某个 Number 子类型的列表，便于读取 Number，但不能随便添加任意 Number。

`List.of(...)` 得到不可修改列表，不能 add；需要修改时用 `new ArrayList<>(source)`。复制容器通常是浅复制，元素对象仍可能共享。遍历时删除元素可考虑 removeIf，不要在增强 for 中随意调用 list.remove。

2. 写一个按 id 查询的方法，找不到时返回 Optional，而不是让调用者立即对 null 调用 title。

<summary>参考解法与检查点</summary>

`tasks.removeIf(task -> task.title().equals("SQL"))` 后 tasks 只剩 1 条，byId 仍保留原来的映射：两个容器不会自动同步。应在统一仓库入口维护数据，避免维护多份不一致的索引。第二题 `Optional.ofNullable(byId.get(id))`，调用方可用 map 和 orElse；不要不检查就 get。
