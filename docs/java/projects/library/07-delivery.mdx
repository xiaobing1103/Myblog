## 这一步要完成什么

前置：[测试与并发验证](./06-testing.mdx)。这一课从干净目录复现项目，确认另一位开发者可以按文档启动、操作和验证。

## 第一步：从干净目录再做一遍

重新解压下载包到新的练习目录，确认没有 target 和 data。进入含 pom.xml 的目录，执行：

```sh
mvn test
mvn spring-boot:run
```

浏览器打开 Java 服务首页，确认空书架正常。把 README 给别人时，不应要求复制你的 IDE 私有启动配置或数据库文件才能成功运行。

如果先前服务仍在占用 8080，应停止它或明确换端口。新的目录意味着新的相对数据路径，不应与旧学习记录混为一谈。

## 第二步：完成一次业务验收

| 顺序 | 操作 | 预期观察 |
| --- | --- | --- |
| 1 | 登记两册 Java Practice | 总册数与可借数都是 2 |
| 2 | 按书名和作者分别搜索 | 结果匹配，页码回到 1 |
| 3 | 借给 Alice | 库存 1，出现未归还历史 |
| 4 | 再借给 Bob | 库存 0，共两条未归还 |
| 5 | 第三次借出 | 409，无额外历史，库存仍为 0 |
| 6 | 归还 Alice 的记录 | 库存 1，时间与状态更新 |
| 7 | 重复归还 Alice | 409，库存仍为 1 |
| 8 | 删除这本书 | 409，图书与历史保留 |
| 9 | 重启服务再查询 | 数据仍在 |

界面禁用无库存按钮时，可用终端请求验证第 5 步；界面只显示未归还记录时，切换范围查看已归还历史。验收应同时检查响应状态、库存和借阅历史。

## 第三步：检查失败与显示边界

- [ ] 字段空白、长度越界、册数为 0 时能得到明确 400 提示。
- [ ] 图书不存在与无库存分别为 404、409，不混成 500。
- [ ] 书名包含引号、百分号、下划线时按文本保存和搜索。
- [ ] 书名包含尖括号时仅显示文字，不执行 HTML。
- [ ] 手机宽度下能阅读列表、填写表单和执行借还。
- [ ] 停止服务后页面能显示网络错误，恢复后可重试。
- [ ] 快速切换搜索或借阅筛选，不让旧请求覆盖新状态。

最后查看浏览器 Console 和 Network。页面没有视觉报错不代表请求都成功，尤其要检查 400、409 与重试行为。

## 第四步：按调用链复盘

尝试不看代码回答：创建借阅经过了哪些类？哪个方法执行条件扣库存？插入借阅失败为什么库存可以恢复？重复归还为什么只能有一次成功？

用自己的话解释这些问题，并与实际代码对照。回答不清时回到 [第 4 步借还事务](./04-borrow-return.mdx)，沿请求重新设置断点。

## 第五步：整理可交付文件

保留源码、pom.xml、README、LICENSE 和测试。target 属于构建产物，data 属于本机数据，不提交到仓库或发给别人作为唯一的启动条件。不要把数据库密码、私人借阅信息和部署密钥塞进公开示例。

项目使用 MIT 许可的新代码，分发时保留许可证。另行下载的开源教材与上游示例有自己的许可要求，按[开源教材专区](../../open-source/index.mdx)的来源和文件说明处理。

## 两项扩展任务

1. 增加“借阅到期日”。先写清默认期限、使用哪个时区定义日期、是否允许续借，再设计字段和测试。
2. 给借阅历史增加真正的分页。目前接口最多返回最近 100 条，应明确页大小上限、总数和稳定排序，不能只给页面加“下一页”按钮。

<details>
<summary>扩展思路与验收要求</summary>

到期日如果按“哪一天”表达，可考虑 LocalDate；发生时间仍用时间点保存。测试固定 Clock，不依赖真实今天；已有借阅如何补到期日也需要迁移策略。

历史分页可沿用图书接口的 `{items,total,page,size}` 结构，并保留创建时间与 id 的稳定排序。覆盖第一页、末页、空页、非法页大小，页面筛选变化时重置页码。两项都应先写契约和失败测试，再改数据库、Service 和前端。

</details>

## 本轮完成后再深入什么

工程使用本机教学配置。需要上线时，应按部署环境补齐登录、权限、生产级审计、备份恢复和数据库迁移，再重新验收。

你可以先阅读 [18 课教材的毕业项目](../../textbook/18-project.mdx)，再进入[开源教材专区](../../open-source/index.mdx)，对照官方项目的目录、测试与 README 练习独立阅读源码。
